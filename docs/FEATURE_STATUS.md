# Feature status

Audit date: 2026-10-21

Status is based on the current source in `src/index.html`, `src/renderer.js`, `main.cjs`, and `preload.cjs`. A visible control is not counted as complete unless its behavior is connected. The project has no database or backend server; settings, drafts, and sessions use browser localStorage in the Electron profile.

## This phase

- Added local push-to-talk recording and a loopback-only Whisper.cpp transcription adapter; local-service responses are parsed and sent into the interviewer follow-up flow.
- Added local resume and document libraries for PDF, DOCX, and TXT. Resume comparisons use an explainable role-fit rubric, show exact text matches/misses, persist the most recent review locally, and explicitly warn that the result is heuristic rather than an ATS or hiring prediction.
- Import is initiated by an Electron native file picker; the renderer cannot submit arbitrary file paths. Files are capped at 10 MB, PDFs at 100 pages, extracted text at 100,000 characters, and scanned-PDF OCR at 20 pages per OCR job.
- Installed the official Whisper.cpp Windows CPU runtime and verified its archive checksum; downloaded the multilingual `base` model and verified the upstream SHA-1. The server passed a local `/inference` WAV smoke test (`HTTP 200`), and the Ollama CLI now lists the four local models after starting its service.
- Added persisted language selection, local Whisper endpoint/mode settings, accessible recording/status states, and a setup guide. Audio requests are limited to 20 MB and cannot target hosted endpoints.
- Implemented the Auto Generate preference as an explicit, default-off opt-in. When enabled, the selected model drafts an answer suggestion after each interviewer question; the suggestion is neither spoken nor submitted on the user's behalf. The setting is saved and restored with interrupted sessions.

- Corrected the live Answer action so the model receives the current interviewer question rather than an injected placeholder line.
- Changed live message insertion to use DOM text nodes and `textContent` for user/model/error messages.
- Connected provider model discovery and chat, with secrets isolated in the Electron main process and encrypted using `safeStorage` when available.
- Wired answer preferences into coaching prompts and added an in-app interviewer-guidance dialog with keyboard support.
- Added interrupted-session recovery, explicit resume, transcript export, individual delete, and elapsed-time persistence to session history.
- Added Ollama/OpenAI-compatible streamed model answers, first-run provider setup, privacy-safe diagnostics, bounded verb-synonym evidence in resume scoring, optional local speech-model selection, live browser speech captions, and three resume PDF layouts. Automated tests passed 55/55 after these updates; manual GUI and real-device speech checks remain outstanding.
- Added editable, confirmed public HTTPS job-link import; source-grounded AI resume-summary suggestions; local Piper/Kokoro speech-output adapters; and a third-party notice inventory. Current automated suite passes 64/64; live external job-page and local TTS server checks remain environment-dependent.
- Added a reproducible Windows portable build plus per-user install/uninstall scripts. Built the package and verified its Electron executable, app entry point, Whisper server/base model, Electron/Chromium license files, and BUILD-INFO metadata are present. `npm test` passes 64/64; the live GUI and clean-account installer flow have not been exercised.
- Added bundled English Tesseract.js OCR for scanned PDFs and an optional loopback-only Stable Diffusion WebUI headshot workflow. OCR language data initializes from local files without network access. The app still needs a live desktop OCR visual test and an installed local image model for end-to-end generation QA.

## Known blockers / limits

- No database exists; persistence is local to the Electron profile and can be cleared by the user or OS profile reset.
- Local offline speech-to-text is included in the Windows portable package. Real microphone end-to-end and clean-account installation tests remain outstanding.
- Hosted provider behavior is covered with a local mock server, but a real provider account and API key have not been used for verification.
- No automated GUI end-to-end harness is present; provider IPC has local mock-server integration tests.
- The resume rubric uses lexical overlap and simple structure/evidence checks; it can miss synonyms and context, so the score must be treated as an editing aid rather than an objective suitability rating.
- Verification: `npm test` passed 13/13 at the time of the phase audit; production dependencies pass `npm audit --omit=dev`. The full audit still reports known issues in the development Electron toolchain; a breaking major Electron upgrade was not applied.
- Latest automated verification after the preparation pages: `npm test` passed 19/19; JS syntax checks passed for the updated renderer, preparation module, main process, and preload. Manual GUI checks remain pending; the local desktop session exposed three same-titled app windows, so a unique safe UI target was unavailable.
